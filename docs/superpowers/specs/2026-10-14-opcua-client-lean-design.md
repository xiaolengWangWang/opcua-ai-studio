# OPC UA AI Studio 精简设计

日期：2026-10-14。状态：当前交付范围。建议版本：0.2.0。

用户确认：**主程序 OPCUAAIStudio.exe 不超过 30 MB；不常用功能暂时不做；先设计再实现。** 本稿取代完整参考清单的实施分期。

## 1. 本次功能范围

| 功能 | 交付行为 |
| --- | --- |
| 服务器连接 | 保留单工作区、Endpoint 发现、现有安全配置、匿名/用户名认证及证书校验 |
| 节点浏览 | 保留逐层浏览与分页；选择对象确定读取范围，选择变量填入单点验证；浏览加入清单时追加并去重 |
| 单点手动验证 | 输入或选择一个 NodeID，单独读取一次；更新该点结果，保留其他点的结果 |
| 读取清单 | 每行一个 NodeID，分批读取；默认 Auto 识别现有支持的标量和一维数组 |
| 全量读取 | 从指定父节点递归发现全部变量，去重后分批读取；显示进度，支持停止，标明范围是否完成 |
| 质量区分 | 显示 GOOD、BAD、UNCERTAIN；请求失败、解析失败、未读取作为执行状态和错误说明单独记录 |
| 筛选与汇总 | 显示点数和各类状态数量；筛选全部、GOOD、BAD、UNCERTAIN、请求失败、未读取 |
| 点位导出 | 保存 CSV，支持导出全部或筛选结果，保留 NodeID、类型、值、质量、状态码、时间及错误 |
| 帮助文档 | 内置离线读取说明，提供单点、清单、全量、质量和导出示例；发行包附使用说明 |
| 现有基础功能 | 保留已实现的写入确认与独立读回、轮询、通讯记录、本机演示和 AI 诊断，暂不扩展 |

本期新增加的功能围绕点位检查与报告导出，使用现有 UI 控件、通讯层与标准库。

## 2. 暂缓功能

- 多服务器并行、完整项目管理、复杂分组和 XLSX 导入导出。
- 原生订阅管理、实时趋势、历史读取、数据回放。
- 新增复杂结构编辑、方法调用、实时/历史事件及告警操作。
- 图像查看器、信息模型关系图、NodeSet 导入导出。
- 动态可配置模拟器、完整 OPC UA 服务器。
- Pub/Sub、OPC Classic DA、RFID/AutoID 和数据路由。
- 新增 AI 能力、自动设备操作、跨平台发行与自动更新。

已有功能继续使用现有实现；后续功能待具体需求出现时单独评估。[完整参考清单](2026-10-14-opcua-client-product-design.md) 保留为研究资料。

## 3. 页面和操作

保留现有“点位与读写”“节点浏览”“通讯与日志”“AI 诊断”页面，增加帮助入口。

点位页包含批量清单、单点 NodeID 输入、单点验证、读取清单、全量读取、停止、质量筛选、汇总和 CSV 导出。结果行选择只确定待验证点，保持批量清单和其他结果。

节点浏览页沿用现有父节点输入和子节点表格，增加“读取此节点下全部变量”。全量范围始终显示，不先重做完整多连接树界面。

写入沿用独立确认流程，并明确当前连接、NodeID、类型和值。手动检查启动时停止当前轮询，保持检查结果可复核。

## 4. 全量读取和质量规则

全量从用户指定父节点开始；层级引用下的对象继续浏览，变量和属性变量加入清单。节点按当前连接及规范化 NodeID 去重，处理分页、重复引用与循环。

默认每批 100 点，适配服务器可识别的批次上限。首期最多遍历 10,000 个唯一节点，超过时说明范围未完成并建议分支读取。取消、连接错误或权限错误保留已经取得的结果与未完成原因。

原始 OPC 质量按服务器 DataValue 保存；客户端类型核对或解析错误不覆盖服务器质量。没有收到该点 DataValue 时，质量未知；请求失败或未读取单独标记。BAD 点也保留其原始状态码和服务器提供的值信息。

“任务完成”说明范围遍历与读取尝试完成，结果可以包含 BAD 或 UNCERTAIN。停止或失败后的报告注明不完整。

## 5. CSV 导出和帮助

导出冻结当前结果及筛选条件，保存前显示行数。使用 UTF-8 BOM，兼容中文、逗号、换行和双引号。64 位整数保持十进制文本；对可能触发 Excel 公式的文本进行保护。

字段包含 Endpoint、NodeID、已知显示名称、类型、值、OPC 质量、原始状态码、执行状态、读取/源/服务器时间、错误、父节点范围、任务 ID 与范围完整性。缺失信息留空，当前命名空间索引适用于当次服务器会话。

帮助示例使用本机演示：读取 Counter 得到 42；验证不存在节点显示 BAD；全量读取六个演示变量；按质量筛选后导出；解释停止后的未读取点。帮助按钮名称与实际页面一致。

## 6. 主程序大小约束

硬上限：**OPCUAAIStudio.exe ≤ 30,000,000 字节**。采用十进制 MB，以最终补齐图标和版本资源后的 EXE 实际字节数验收。

本次核对的现有 v0.1.0 主程序为 **27,776,000 字节（27.776 MB）**，相对上限还有 **2,224,000 字节**。此数据来自现有产物，精简版新增功能完成后需要重新构建测量。

| 项目 | 实施规则 |
| --- | --- |
| 构建硬检查 | Windows 构建在写入图标/版本资源后检查主程序大小；超过上限直接失败 |
| 构建清单 | 记录 `exeBytes` 和 `exeLimitBytes`，使发行时可以复核 |
| 编译方式 | 沿用 `-trimpath`、`-s -w`、`no_emoji`、Windows CGO SQLite 和现有静态链接配置 |
| 新增依赖 | CSV 使用 Go 标准库；帮助使用现有 Fyne 控件；新功能优先复用现有代码 |
| 体积余量 | 每个功能完成后关注主程序大小；接近上限时先检查新增依赖和嵌入资源 |
| 默认发行 | 沿用已有 GUI、CLI、模拟器和说明的打包方式；30 MB 验收针对主程序 EXE |

认证、证书校验、写入确认和独立读回沿用现有实现。新增功能的体积以最终构建实测为准。

## 7. 验收标准

1. 单点验证更新对应点，其他结果及批量清单继续保留。
2. 清单及全量读取分批运行，部分 BAD 与 UNCERTAIN 不丢失。
3. 全量任务支持停止，结果和导出明确显示范围完整性。
4. 筛选后操作仍对应正确 NodeID；导出行数与选定快照一致。
5. 原始 OPC 质量与请求、类型核对、解析错误分别记录。
6. CSV 中文、精度、转义和文件保存错误得到验证。
7. 用户按离线帮助完成“演示 → 单点 → 全量 → 筛选 → 导出”。
8. 现有安全连接、只读默认、写入确认和记录关闭流程通过回归验证。
9. 最终 Windows 主程序不超过 30,000,000 字节，发布清单与实际 EXE 一致。

本次按精简范围形成实现计划并完成后发版；暂缓功能不列入本次任务清单。
